# Bug 排查材料清单

当输入证据不足时，输出给工程师使用的最小材料清单，由工程师判断如何联系客户并转发。Skill 不绕过工程师直接要求客户执行命令，也不保存这些材料为可复用客户环境配置。

## 清单生成原则

每一项材料都要说明：

- 材料名称和用途；
- 必需还是可选，它用于区分哪些假设；
- 采集对象、故障时间窗、时区和所属节点；
- 可直接复制的最小命令或界面操作路径，以及是否需要 `sudo`；
- 预期格式、文件大小和成功标志；
- 可能包含的敏感信息、脱敏要求和替代方案。

优先请求原始文本或原始日志文件，截图仅用于界面状态、无法导出的弹窗或远程现场。已有材料不重复索取；缺失项按“首轮必需→假设定向→高成本取证”分批给出。

## 常用首轮材料

仅选择与当前问题相关的项：

| 类别 | 常用材料 | 参考采集方式 |
|---|---|---|
| 问题描述 | 实际/期望现象、影响范围、复现步骤、频率、首次发生时间、故障前变更 | 用结构化文字说明，时间带时区 |
| 客户端信息 | 客户端版本、安装包类型、组件/服务版本 | 客户端“关于”页或已知版本命令 |
| 系统信息 | 发行版、内核、CPU 架构 | `cat /etc/os-release`; `uname -a`; `uname -m` |
| 故障日志 | 客户端、目标 service/user service、故障窗口内核日志 | 限定 unit、boot 和 `--since/--until`，不导出全量 journal |
| 进程结果 | 退出码、signal、PID/TID、崩溃/core 是否存在 | 服务状态、客户端退出提示或限定日志 |
| 桌面现场 | 桌面环境、X11/Wayland、弹窗原文和原始图片 | `echo "$XDG_CURRENT_DESKTOP $XDG_SESSION_TYPE"` 或界面查看 |

## 按假设追加

- 资源或被杀：cgroup 限额与 events、OOM 证据、故障前后资源趋势。
- 权限：执行身份、逐级路径权限、ACL、挂载状态、SELinux/AppArmor denial 或沙盒声明权限。
- 存储：目标挂载、文件系统/块设备、空间/inode、故障窗口 I/O 和文件系统错误。
- 网络：目标域名/端口、DNS、路由、TCP、TLS 和应用超时分层结果；pcap 单独授权。
- 图形/设备：session、display manager/合成器、DRM/GPU/驱动、设备枚举与热插拔时间线。
- 内核/驱动：oops/panic 完整上下文、内核版本、taint、模块、固件与最近变更；vmcore 单独授权。
